# Solution Bundler

یک برنامه‌ی Windows برای انتخاب پوشه‌ی یک Solution، انتخاب پروژه‌ها یا زیرپوشه‌های دلخواه، انتخاب پسوند فایل‌ها و تجمیع محتوای آن‌ها در یک فایل متنی UTF-8.

پس از انتخاب Solution، پروژه‌ها و پوشه‌های موردنظر را در درخت سمت راست تیک بزنید، روی «اسکن پسوندها» کلیک کنید و سپس پسوندهای لازم را انتخاب کنید. انتخاب یک پوشه شامل تمام زیرپوشه‌های آن نیز می‌شود.

کادر جست‌وجوی بالای درخت، پروژه‌ها و پوشه‌ها را مانند Solution Explorer فیلتر می‌کند و مسیر والد نتایج را نگه می‌دارد. انتخاب‌های قبلی هنگام جست‌وجو یا پاک کردن فیلتر حفظ می‌شوند.

برای سنجاق‌کردن یک شاخه، نام آن را در درخت انتخاب کنید و دکمه‌ی «★ افزودن Favorite» را بزنید. برای حذف، همان گره را در بخش علاقه‌مندی‌ها انتخاب و «حذف Favorite» را بزنید. این دو فرمان در منوی راست‌کلیک گره‌ها نیز موجودند. برای نمونه، افزودن پوشه‌ی `Security` آن را همراه با تمام پروژه‌های زیرمجموعه در بخش «علاقه‌مندی‌ها» نمایش می‌دهد. علاقه‌مندی‌ها بین اجراهای برنامه حفظ می‌شوند.

پس از انتخاب پسوندها، حجم تقریبی خروجی و تعداد فایل‌ها پیش از تولید نمایش داده می‌شود. بعد از تولید نیز می‌توان خود فایل یا پوشه‌ی محل آن را مستقیماً باز کرد.

آخرین پوشه‌ی Solution انتخاب‌شده در تنظیمات کاربر ذخیره می‌شود و در اجرای بعدی برنامه به‌صورت خودکار بارگذاری خواهد شد.

## SQL Server

دکمه‌ی `SQL Server...`، Connection Stringهای بخش `ConnectionStrings` در فایل‌های `appsettings*.json` کل Solution را پیدا می‌کند. پس از آزمایش اتصال، جدول‌ها در یک درخت `Schema → Table` نمایش داده می‌شوند؛ انتخاب یک Schema تمام جدول‌های آن را انتخاب می‌کند. تعداد رکوردهای ابتدایی هر جدول قابل تنظیم و مقدار پیش‌فرض آن ۱۰۰ است. داده‌ها به‌صورت بخش‌های tab-separated به انتهای فایل متنی افزوده می‌شوند و خود Connection String یا رمز آن در خروجی نوشته نمی‌شود.

## Redis

دکمه‌ی `Redis...` مقادیری مانند `Cache: localhost:6379` را از تنظیمات کل Solution پیدا می‌کند. Database، الگوی کلید، حداکثر تعداد کلید و حداکثر اعضای هر مقدار قابل تنظیم هستند و مقدار پیش‌فرض محدودیت‌ها ۱۰۰ است. نوع، TTL و مقدار String/List/Hash/Set/Sorted Set به خروجی افزوده می‌شود؛ Connection String و رمز Redis در فایل نوشته نمی‌شوند.

## اجرا

```powershell
dotnet run --project .\SolutionBundler.csproj
```

## ساخت فایل اجرایی مستقل

```powershell
dotnet publish .\SolutionBundler.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

خروجی در مسیر زیر ساخته می‌شود:

`bin\Release\net10.0-windows\win-x64\publish\SolutionBundler.exe`

پوشه‌های `bin`، `obj`، `node_modules`، `.git`، `.vs`، `.idea`، `.vscode` و `packages` در اسکن نادیده گرفته می‌شوند.
